RESEARCH REPORT

Lazy Vibes

When an adversary tells their robots:

"Help me pentest."

Noam Rotem and Ran Locar, Cybercyberlabs.com

29 September 2026

TL;DR

We found a server holding the working files of an operation targeting companies in several countries. It held scanners, exploit scripts, copied source code, credentials, export records, and agents that fetch commands and send back the results.

The targets included Spanish dental businesses, software companies, a Kestra workflow deployment in Germany, SonicWall appliances, and applications belonging to Italian manufacturer Valsir. The Business Central export analysis recorded 7,186 customer rows and 731 vendor rows, including an entry that may contain demonstration data. Ten copied repositories account for another 9,483 files, and the operator reported access to 37,579 contacts through MarketingBoost's CRM integration.

The working environment included OpenCode running as root, target lists grouped by industry, and proxies labeled as supplied by a client. Russian appears in the project instructions, script comments, and keyboard-layout mistakes in shell history.

The discovery

We recovered 364 files across 95 directories from the server at 89.124.67[.]72:8443. Alongside the scanning and exploit tools were copied source repositories, business-data exports, and the operator's working files. Dated records in the collection span 31 August through 28 September 2026.

The operator kept project instructions, target lists, and notes for work they described as pentesting. Reading these alongside the shell history let us trace the work on individual systems, from reconnaissance to attempts to gain access. The copied repositories and export records showed what had been collected, while the job notes described further access claimed by the operator.

How the operation worked

The target lists cover Spanish dental groups and food companies, British healthcare and industrial portals, Canadian healthcare organizations, and Italian manufacturers. The Italian reconnaissance alone covered approximately 250 domains on 27-28 September. The accompanying tools search for subdomains, crawl websites, scan directories, copy exposed Git repositories, and test application vulnerabilities. The collection also includes scripts for BeyondTrust, TeamCity, Kemp LoadMaster, SmarterMail, and Langflow.

The project instructions repeatedly call for finding leaked credentials. Copied application source code provided one route to those credentials, as the repository findings below show. Other project records describe Business Central exports, changes to Kestra workflows, database access, and attempts to reach internal systems.

Keeping access

The shell agents ask the server for a command, run it, encode the output, send the result back, and repeat. Their URLs point to http://89.124.67[.]72, using port 80. Each command's output is capped at 24,000 bytes before Base64 encoding and sent in chunks of up to 3,000 encoded bytes.

A separate script attempts to append an SSH key to the root and service accounts' authorized_keys files, then sends a callback containing the machine's hostname. Another, cmd201.sh, probes other hosts on ports 22, 445, and 3389 and reads local Tomcat configuration files. The Python listener oob_http.py is configured to receive callbacks on port 8000 and write them to oob_hits.log.

The recovered file configs-revs.json contains saved versions of a Kestra workflow. These include commands to download and launch a Komari agent and test outbound connectivity. The workflow history also names kaptanporncanli.com as a callback destination. The download, reporting, and agent-server addresses are listed in the detection section below.

Indicators and detection

The following destinations and request patterns appear in the recovered scripts and workflow configurations.

smallest-relatives-retrieval-henry.trycloudflare.comHTTPS request to /komari-agentAlternative agent download.

The polling agent requests commands through /c and sends output to /r/. Its query includes the hostname and last task number, while the result URL includes a task number and chunk sequence. The script appends.ora2 to the hostname it reports and sleeps for eight seconds after each cycle. Commands and network requests add to that interval. It invokes curl, base64, head, and tail from a shell.

The SSH-key script, a.sh, attempts to append a key to the root and service accounts' authorized_keys files before sending a hostname callback to /zb/. The reconnaissance script, cmd201.sh, reads properties files under /home/service/tomcat/webapps and uploads its output to /r/zbx201_office. In the Kestra workflow history, the Komari download commands save the agent as ka, and the launch command points it to tz2.5671234.xyz.
